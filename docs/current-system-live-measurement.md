## 行动执行与有效活动

283 次新逻辑行动决策：246 次按结果应用，29 次低置信度改为等待，3 次失败，5 次在测试暂停时暂存。共有 275 次交给游戏执行，约 178.5 次 / 现实分钟；其中包含移动和等待，不能称为 275 次生产性活动完成。

游戏窗口内实际记录：35 次工作完成、63 次阅读／休息完成、18 条对白、9 个突发事件。另有 67 条户外事件，其中包含出发、开始和结算，不能当成 67 次户外活动完成。这些结果说明本轮不是仅推进时钟而没有居民活动；部分完成事件来自起始存档已经在途的任务。

模型选择以避雨和休息为主：`shelter` 88 次、`rest` 52 次，表明本窗口有明显天气和状态特征，不代表所有场景的平均负载。

## 速率上限与单个行为生效延迟（补充统计）

当前界面及 API 允许的最高目标为 6×，相当于现实 5 分钟 / 游戏日，或每现实秒推进 4.8 游戏分钟。模拟循环名义频率为 10 Hz（100 ms 一次 tick），并不表示每个角色每秒调用模型十次。上述 92.42 秒实测的滚动倍率最高达到 6×，全窗口平均为 5.3887×，按该平均折算为现实约 5 分 34 秒 / 游戏日。尚未修改速率上限或运行饱和压力测试，因此 6× 是当前产品配置上限，不能称为模型系统的极限处理能力。

对本轮 275 次真正提交执行的行动（246 次原选择、29 次规则覆盖）单独统计，以 `appliedAt - queuedAt` 测量后端行为生效延迟：

| 延迟阶段 | P50 | P95 |
|---|---:|---:|
| 调度排队 | 1 ms | 8 ms |
| 完整模型调用，包含重试与响应验证 | 486 ms | 2,474 ms |
| 返回后到行为提交 | 1 ms | 8 ms |
| 端到端：可调度记录到后端行为生效 | **490 ms** | **2,476 ms** |

端到端平均 871 ms，最快 324 ms，最慢 9,601 ms。分位数按各行独立计算，不能相加。3 次失败与测试结束暂存的 5 次行动没有可用的执行生效时间，未计入这 275 次；若统计全部 283 次调用返回（含失败和暂停暂存），调用 P95 为 2,556 ms，最慢 11,103 ms。

这不是事件发生到前端可见动画的全程延迟。`queuedAt` 在调度器确认角色可决策时记录，不含此前的持续活动、1.5 秒调度节流及其前面的等待；也未测浏览器广播、渲染或行动完成时间。走路、工作、钓鱼等提交后仍需执行，其中本地工作持续 40 游戏分钟，在目标 6× 下仅执行阶段就需约 8.33 秒，另加判断、路程和同步等待。

全镇应用行动吞吐为 275 / 92.42 = **2.98 次 / 现实秒**。单个角色相邻决策启动间隔的中位数为 **7.46 秒**（259 个间隔），最短约 **1.50 秒**；代码有每角色约 1.5 秒的最小自动行动调度间隔，因此最多约 0.67 次 / 秒，实际还受正在行走、持续活动、模型响应和世界同步约束。不同角色可以并发，不能把全镇 2.98 次 / 秒当作每个角色的决策频率。

统计明细：`output/system-measure/action-latency.json`。本补充只读取已有真实运行记录，没有新增付费调用。

本次不能回答替换版会快慢多少或贵多少。下一组若使用 DS 替换 Jev，应沿用相同存档、调度、角色上下文和测试时段，同时明确 Choice / Score / Noul 与置信度规则如何适配；模型决定导致的不同活动轨迹也必须计入系统结果。
