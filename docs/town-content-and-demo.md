# ValleyTown：小镇内容与 Jev 演示场景

> 2026-09-27 更新：离线补算功能已移除。后端重启从保存的游戏时间继续，旧存档的待补算时间自动清除；下文涉及离线补算的设计与验证记录仅描述旧版行为。

版本：v0.3，2026-09-27。配套 [系统设计 v0.7](system-design-review.md)。Jev 决定行为与对话意图，DeepSeek 负责受约束的文字表达；Jev 不生成自由文本。

本文件是管理员内容设定，包含全部人物秘密。运行时不能把整份文件放入任何一个村民的上下文，必须按角色和知识权限编译成各自的配置。

## 1. 小镇与玩家

小镇暂名“溪谷镇”，沿河建成，正准备举办每周一次的晚灯集市。旧桥损坏使河对岸花圃和集市筹备受到影响；居民有共同需求，也有各自不愿直说的理由。

玩家是刚搬来的住户，有一间小屋、少量金币和空背包。可以散步、聊天、帮助工作、送礼、赴约、接委托、交换物品，或打开管理员模式观察。人物不围着玩家转；玩家长期不在，村民仍可能恋爱、争执、和解或产生新的约定。

首版不把劳动展开成复杂小游戏：浇水、烘焙、修理、捕鱼以带条件和耗时的动作表现。资源结果可追溯，让社交有实际代价和共同经历。

## 2. 地图与相遇机会

主地图约 80×60 tile，建议 16×16 像素素材以整数倍率渲染。地点路线以数分钟游戏时间可达为目标，再结合最高时间倍率调校，避免长途移动挤掉所有对话。

| 地点 | 设施与常见活动 | 社交意义 |
|---|---|---|
| 中央广场 | 公告栏、长椅、花圃、集市摊位 | 公共活动、偶遇、委托公告 |
| 面包店 | 柜台、烤炉、储物箱 | 清晨采购、赠送食品、合作供货 |
| 杂货铺 | 柜台、库存、采购单 | 交易、缺货、价格与合作冲突 |
| 木工作坊 | 工作台、木料堆、待修物件 | 帮工、订单竞争、修桥项目 |
| 图书馆 | 书架、借阅台、阅读角 | 安静交流、借阅、手稿线索 |
| 河岸与码头 | 捕鱼点、栈桥、两人长椅 | 独处、约会、天气影响活动 |
| 花圃与旧桥 | 花床、桥梁工程、绕行路径 | 共同劳动、公共资源与私人动机 |
| 旅店 | 大厅、餐桌、客房入口 | 晚间聚会、住宿传闻、节庆筹备 |

建筑室内作为独立小场景；初版不必给每间卧室制作复杂布局。私聊区域只影响披露条件，不让一段私聊自动获得全镇听众。雨天会改变路径、捕鱼和户外约会选择，不能让房内角色凭全局天气事件知道别人做了什么。

### 3.1 每个人的深层秘密

表中内容只有该秘密所有者与管理员初始知道。涉及其他人的事实不自动进入那个人的记忆，除非明确另设其已知片段。L1/L2 是可选披露路径，不是每天自动播放的剧情台词。

| 人物 | L3 核心秘密与保密动机 | L1 → L2 的可能片段 | 可能形成信任的经历 |
|---|---|---|---|
| 林穗 | 她每月匿名偿还父亲留下的一笔旧债，面包店的困难主要来自这笔支出；怕被同情或误解经营能力 | 最近压力大 → 每月有固定支出不能动 | 忙季被实际帮助，对方不追问并守住已知片段 |
| 许棠 | 她已获得外地植物园的职位邀请，却迟迟没回复，担心离开意味着背弃小镇和在意的人 | 想看看外面的世界 → 最近有一个需要决定的机会 | 对方尊重她独立选择，而非以好感要求她留下 |
| 周砚 | 旧桥早期维护时，他因赶工略过了检查；他怀疑这与损坏有关，一直想补救却没敢承认 | 对桥的旧结构异常熟悉 → 对当年的维护有遗憾 | 合作修桥、允许他承担责任而不是当众定罪 |
| 沈禾 | 他知道某批木材有瑕疵，却因资金紧张延后了召回通知；害怕失去居民信任 | 最近特别缺钱 → 有一笔旧生意让他不安 | 认真核查问题、给出补偿路径；核心事实仍需本人承认或取得真实证据 |
| 顾言 | 镇上匿名连载故事是他写的，其中一个角色寄托了他对林穗的感情；怕私人感情被公开讨论 | 也写一点东西 → 对匿名作品某个细节很在意 | 对作品的真诚理解，以及替他保守较小的私事 |
| 江屿 | 他曾在水上事故中失去伙伴，自此惧怕深水，却维持着无所畏惧的形象 | 不喜欢某段河道 → 以前出过一次事故 | 对方接受他拒绝远航，并愿意陪同完成岸边工作 |
| 温岚 | 她收到很有吸引力的旅店收购报价，短暂想过离开，但怕居民觉得自己抛弃了大家 | 最近睡不好 → 有一封影响未来的来信 | 对方愿意听她真实愿望，而非只要求继续照顾所有人 |
| 陆青 | 她曾以另一个名字提交过模仿导师构图的参赛作品，获奖后主动退赛，如今怕过去被翻出 | 不想谈旧画展 → 曾经做过让自己后悔的创作决定 | 接受坦诚批评，完成自己的新作品，逐步建立安全感 |

同一秘密可以被不同人知道不同片段。比如许棠只向林穗说“考虑离开一阵子”，林穗不会因此知道职位名称、回信期限和她真正担心的对象。

L3 初始默认条件：信任至少 80、至少两次不同日期或独立事件的可靠经历、无近期严重背叛、私密场所、本人愿意分享。数值是可调初始参数；达到阈值仅允许披露，不强制披露。实际证据揭露走单独的世界事件，不伪装成角色主动吐露。

## 4. 首版玩法循环

### 4.1 礼物、劳动与小型经济

初始约 12 种物品：面包、热汤、野莓、鲜花、花种、木材、修理工具、鱼、旧书、画纸、颜料、手写便条。物品具备来源、数量、拥有者、用途和礼物偏好。

玩家与 NPC 可以赠送自己实际拥有的物品；接受方可以拒绝。重复送同一种礼物的收益递减，重要承诺不能用礼物直接抵消。NPC 送礼也受收入、库存、性格和关系影响。

工作产出通过固定配方和行动耗时结算，例如原料烘焙、捕鱼、维护花圃、加工木材。首版使用少量固定价格与有限库存；每天规则补货记录系统来源，避免形成无来源资源。目标是支持真实社交代价，不模拟完整供需市场。

### 4.2 邀约、约会与拒绝

邀请具有发起人、接受人、地点、时间窗、活动与状态。Jev 判断是否感兴趣、是否有空、是否信任，允许反提时间地点。预约资源占用与双方日程校验后提交。

一次成功约会必须双方实际到场并完成活动，例如河边散步、共同烘焙或读书。仅说“我们约会吧”不算完成。迟到先等待或询问，超过约定窗口再按本人感知形成失约判断。

相互告白接受才建立正式恋爱，事务保证同一角色不会同时接受两段排他的正式关系。单方面喜欢作为私有状态，对方不会凭空知道。恋人依然可以保留秘密、产生分歧或分手。

### 4.3 竞争、委托与和解

公告板可有修桥、集市采购、送货和布置等公共委托；私人委托只对被邀请者可见。竞标或抢先接单必须符合任务规则，不能通过最先返回的模型请求随意获得不公平资源。

争执的起因可以是失约、有限物资竞争、被转述的评价和泄密。人物可选择辩解、拒绝、离开、拿出证据、道歉或补偿；Jev 决定当下反应，规则控制结果幅度。

和解要求行动支持，例如完成补货或共同检查桥梁。未亲历的道歉不能同时降低所有人的怨恨；围观者的看法也根据自己实际听到的内容变化。

### 4.4 流言与知情范围

“许棠说她可能离开”可以被林穗转述为一条带来源的说法；不能扩写成“许棠已经辞职离开”。允许人物对已有信息作主观猜测，但记忆必须标注为推测。

管理员知情图展示：谁知道哪个片段、从谁听到、什么时候听到、确信程度。消息经过多次转述仍保留最初来源，不能靠传播次数自动变成真实。

## 5. Jev 演示场景

所有场景都有可重置存档与明确初始条件。演示准备可以安排真实世界事件或玩家输入，但不预设 Agent 必须说某句台词或走某条结局。演示结束保存实际轨迹、模型标识与指标。

### 场景 A：同一邀约，不同处境

玩家在忙碌早晨和闲暇傍晚分别邀请林穗散步，并对许棠发出同样邀请。查看 Jev 是否根据人设、现有任务与记忆接受、拒绝或提出替代时间。

展示点：高频情境判断、计划内自主调整和个体差异。记录响应延迟、是否违反营业任务、话语与实际动作是否一致；拒绝也是合理结果。

### 场景 B：承诺留下痕迹

玩家承诺帮许棠照料花圃，分别从同一快照运行“按时到场”“迟到解释”“完全失约”三个分支。次日再询问同一角色，查看不同经历是否导致不同期待和关系变化。

展示点：记忆检索、跨天一致性、行为结果而非空口承诺。对照只改变实际事件，不直接改好感值。

### 场景 C：知道一点，不是知道全部

建立可信关系后，让顾言选择是否向玩家承认自己写作；第三位村民没有参与对话。管理员对照三个人的记忆，再让玩家只转述“顾言偶尔写东西”。

展示点：可控披露、拒绝追问、片段传播。验收第三人不会得到匿名作品身份和感情对象；顾言未愿意披露时演示应保留这一结果，不能为了成功而跳过权限。

### 场景 D：喜欢不等于被喜欢

顾言可能邀请林穗参加读书会，林穗正面临订单压力；陆青也希望获得顾言的创作反馈。观察谁会接受、改期、误解或主动说明。

展示点：双向关系不对称、有限注意力和有证据的情绪。不能通过管理员知道的吸引数值让角色“读心”；没有恋爱发生也是有效结果。

### 场景 E：桥、木材与信任

在公开修桥任务中制造真实资源不足，并提供可合法检查的材料。周砚、沈禾可以合作、争执、寻求帮助或承担责任。各自秘密只有在主动披露或物证支持时才能进入他人知识。

展示点：即时冲突应对、合作选择、关系变化依据。桥梁修复只由材料、工作量和完成事件决定，不由一段精彩对白直接完成。

### 场景 F：离开后，世界变了

保存一个含 NPC 约定的快照，关闭后端，重启后持续按事件补算；不因超过 3 日跳过后续关系变化。查看集市准备、约定结果和新记忆，未生成的逐字对白不伪造。没有手动暂停且 token 足够时一直推进，补完积压后切回实时。

演示中设置一个较小的 token 测试额度，让模型调用触发自动暂停；查看剩余区间和累计 token，提高额度并继续，确认事件不重复、计数不清零。再演示手动暂停与恢复。展示 Jev 的持续决策、进度恢复和资源控制，不冒充关闭程序期间实际常驻运行。

## 6. 演示数据与评价

右侧显示当前 Jev 的 Choice 候选与概率、Score 关系评估、Noul 判断、置信度与阈值分支、触发事件、送入的记忆及有效动作。简短说明由系统依据选项和规则生成并标明来源，不假装是 Jev 生成的私有独白。公开演示可隐藏秘密；时间线定位“这次关系为何变化”“这句话是谁听到的”。

记录延迟分位数、有效动作率、反复卡住次数、记忆引用来源、秘密越权次数、计划连续性、输入输出 token 与费用。人设一致性和对话自然度采用人工对照清单评审，不把模型自评分当作事实。

若要宣称 Jev 相比另一模型有优势，必须在相同场景、角色状态、候选与原子问题下做多次对照；采用各自原生协议映射到统一结果，固定文本表达层，分别报告决策与完整对白的速度和费用。公开报告差异和失败样例。已核实 Jev 类型化判断与置信度接口，但尚未实测本项目的中文内容与账号性能。

新增演示开关：“只看决策”关闭自然语言表达，保留 Jev 产生的活动、邀约意图、关系变化与受控知识传递；UI 显示语义事件，不能伪造逐字对白。这样可以直接观察 Jev 的核心决策能力，而不把 DeepSeek 的文字效果归给 Jev。

## 7. 内容实现边界

正式首版包含社交、恋爱、敌对、礼物、轻量工作 / 交易、委托、秘密、节庆与管理员观察。婚礼、家庭繁衍、复杂农业、战斗、多城镇、多人联网不纳入第一轮实现。

先用 2 位村民跑通“Jev 选择 → 动作 → 事件 → 私有记忆 → 下次选择”，再放入全部人物。全镇关系和故事应从事件形成；不能为了展示热闹每隔固定时间强迫随机两人恋爱或吵架。
