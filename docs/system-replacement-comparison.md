# 整套系统实测：保留 Jev 与替换为 DeepSeek

2026-09-27，分别运行当前混合系统和“原 Jev 部分全部使用 DeepSeek”的隔离版本。两轮从同一个未推进的 24 人主存档起点（游戏分钟 6850.829663）出发，目标 6×，核心源码核对一致。主系统代码和主存档未被替换测试修改，测试已经停止，无在途请求或新增未知用量预留。

本次观察到：替换版没有使游戏时间推进变慢，但每游戏小时费用约为当前版的 **3.03 倍**；行动中位延迟增加，P95 反而降低，同时改变了人物活动分布。这是每组一次的系统实测，不是模型排名或稳定性能倍数。

## 替换范围

当前：Jev 选择行动、判断社交意图和关系评分、校验对白；DeepSeek 负责原有规划和文字表达。

替换：所有 `ModelGateway.jev` 调用改用 `deepseek-flash`，关闭思考，开启 JSON 输出。原有 DeepSeek 调用保留。人物上下文、候选生成、本地执行规则、12 / 3 / 4 任务池、同步节点和重试策略保持一致。自由对白依然是“意图 → 表达 → 校验”三个串行阶段；没有通过合并阶段减少网络请求。

选择题单次最大输出 128 token；多问题最大输出为 `max(128,96 × 问题数)`。严格检查候选、评分和范围，不在 JSON 解析失败后伪造动作。没有生成概率分布；原阈值使用 DS 自报 confidence，**其含义未校准为 Jev 原生置信度**。因此这是明确适配策略下的可运行替换系统，而非数学等价替换。

替换代码位于 `output/system-measure/replacement-code`，生产代码未切换。起始快照哈希和协议保存于 `replacement-manifest.json`。

## 整体指标

| 指标 | 当前 Jev + DS | Jev 部分替换为 DS |
|---|---:|---:|
| 北京时间 | 18:50:20–18:51:53 | 19:03:08–19:04:28 |
| 测量窗口 | 92.42 秒 | 80.134 秒 |
| 停止原因 | 计划采样窗口结束 | 下次请求无法预留足额预算 |
| 推进游戏时间 | 398.42 分钟 | 379.22 分钟 |
| 平均实际倍率 | **5.389×** | **5.915×** |
| HTTP 成功 / 尝试 | 305 / 315 | 210 / 214 |
| 本地费用估算 | **¥0.202957** | **¥0.584972** |
| 每游戏小时费用 | **¥0.030564** | **¥0.092553** |
| 新增未知用量预留 | ¥0 | ¥0 |
| 输入 / 输出 token | 678,379 / 38,058 | 287,669 / 4,842 |

替换版配置新增 DS 预算空间约 ¥0.60，原 Jev 没有产生新请求。因仍需为下次请求预留输入和最大输出，测试在实际费用未达到 ¥0.60 时提前暂停；不是崩溃。为了不突破已告知的测试费用上限，没有追加预算凑满 90 秒。

两轮费用合计约 **¥0.787929**，保存在各自独立的测试账本中，没有写回主账本；供应商账户会承担真实费用。价格为项目本地估算，Jev 汇率 7，DS 使用配置的高峰价格并抵扣实际缓存命中，供应商账单为准。替换版缓存命中 14,848 / 287,669 输入 token，约 **5.16%**。

两轮时长和行为轨迹不同，因此采用每游戏小时费用比较：替换版约 **3.03 倍**，即当前版在这两轮观测中约低 **67%**。这不是长期费用预测，也不是强制同一动作序列的请求重放。替换版 token 更少仍然费用更高，表明跨服务不能以 token 总数直接衡量经济性。

## 行动延迟与吞吐

| 指标 | 当前 Jev + DS | 替换版 |
|---|---:|---:|
| 新逻辑行动决策 | 283 | 194 |
| 完整逻辑调用 P50 | 490 ms | 706 ms |
| 完整逻辑调用 P95 | 2,556 ms | 1,763 ms |
| 最慢逻辑调用 | 11,103 ms | 9,995 ms |
| 行动排队 P95 | 6 ms | 1 ms |
| 行动平均在途数 | 2.75 | 2.06 |
| 按模型结果应用 | 246 | 185 |
| 低置信度改为等待 | 29 | 0 |
| 状态变化拒绝 | 0 | 3 |
| 失败 | 3 | 5 |
| 暂停时暂存 | 5 | 1 |

完整调用统计包含失败和重试；替换版的 5 次失败中有一次预算预留失败，没有发出 HTTP 请求，其余 4 次为 JSON 解析失败。HTTP 返回成功不等于最终行动应用成功。

替换版单次行动中位耗时增加约 **44%**，P95 降低约 **31%**，游戏平均倍率却高约 **9.8%**。这说明本系统中的异步执行、调用密度和长尾等待比单个请求的中位速度更能决定整体倍率。两轮行动排队都很短，未观察到持续排队瓶颈。

当前版有 10 次明确连接前失败，替换版有 4 次，都会释放预留；网络时段不同，不能把本次较好的长尾全部归因于 DS。同步等待的一秒采样计数分别为 1 / 89 和 0 / 81，不代表替换版绝无短暂阻塞。**本次不足以证明替换版稳定快 9.8%，也不支持“替换后必然更慢”。**

## 行为与可靠性

| 游戏窗口内完成或生成的事件 | 当前版 | 替换版 |
|---|---:|---:|
| 工作完成 | 35 | 40 |
| 阅读／休息完成 | 63 | 22 |
| 对白 | 18 | 12 |
| 突发事件 | 9 | 7 |

这些计数含起始存档已经在执行的活动；不同窗口、不同选择会改变事件数量，不能把工作更多直接等同于角色质量更高。替换版更少休息、更多选择避雨，置信度没有触发过原有的低置信度等待阈值，而当前版触发 29 次。阈值仍然是同一个数值，但两种评分并未校准，人物行为因此并不等价。

替换版 4 次 API 成功返回的动作响应无法解析为完整 JSON，均没有提交动作。这些响应的供应商输出用量为 19 / 23 / 19 / 23 token，低于 128 的上限；现有记录不足以确定具体生成原因，不能直接归咎于输出上限截断。本次没有增加自动修复或补发，以免改变既定重试策略和费用。

对白表达仍为原来的 DS，替换版仅有 2 次表达与 2 次校验，当前版分别 3 次。没有玩家端完整回复计时，不能凭这些零散请求样本给出完整对白提速结论。

## 对系统选择的含义

如果重点是长期运行成本，这两轮实测支持保留 Jev：在本次工作负载下，每游戏小时费用明显更低。

如果重点是整体游戏推进速度，本次替换没有造成退化，但证据不足以据此决定切换。切换前还需要解决 JSON 失败策略、重新校准置信度阈值，并在多个起始情境、交替运行顺序下重复测试。当前结果已经说明不能用“模型中位延迟较低”直接推导“整套系统更快”。

## 复现与产物

- `scripts/prepare-deepseek-replacement.py`：检查基线核心源码、复制隔离代码与 SQLite 快照，已有目录时拒绝覆盖账本。
- `scripts/deepseek-replacement-adapter.ts`：Choice / Score / Noul 的 DS JSON 适配与严格验证。
- `scripts/measure-current-system.ts --deepseek-replacement`：真实运行，会产生模型费用。
- `scripts/analyze-system-measure.py --deepseek-replacement`：只读分析。
- `output/system-measure/comparison.json`：两组完整汇总与比值。
- `output/system-measure/replacement-summary.json`：替换版分项用量、缓存、错误和行为统计。
- 类型检查通过；本地验证覆盖合法三类返回，以及非法候选、置信度、评分和 Noul 拒绝；隔离网关路由已验证。没有为测试修改生产模型路由。
