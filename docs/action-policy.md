# 动作库与按需规划

本地规则决定什么能做，Jev 决定此刻做什么，DeepSeek 按需提供可复用的阶段目标。

## 使用入口

观察者视角 → 居民面板 → Jev 决策实验室 → 动作与规划。可查看当前地点的候选动作、候选分类、当前本地任务、每日规划状态、重规划次数与开放原因。实时执行追踪也会显示候选所属分类和决策触发原因。

## 动作注册表

`server/actions.ts` 的 `actionRegistry` 定义能力和条件，`professions` 定义 24 种职业的工作表现与产物。`buildActions` 根据当前人物和世界生成最多 24 个具体候选；每次模型返回后，`validateAction` 再校验位置、身份、时间、资源及事件资格。

- 通用：等待、休息、前往目的地、寻找屋檐。
- 场所：图书馆阅读、杂货铺购买鱼饵或箭矢、旧桥／集市捐助，以及钓鱼、篮球、慢跑、登山、打猎。
- 身份：24 种职业的本职工作；医生可在诊所帮助附近精力不足的成年居民恢复体力。尚未增加独立的疾病诊断、门诊排队或复杂职业经济系统。
- 情境：附近交谈、赠礼、邀约、表白、婚姻／家庭讨论、纠纷与调解。原有谋杀概率门槛、双方同意与司法证据规则继续生效。
- 规划：满足条件时提供 `replan`。

远处候选明确包含目的地和抵达后的活动，例如「去图书馆阅读 20 分钟」。Jev 一次批准整项活动，`travelIntent` 保存活动、角色版本与 180 游戏分钟有效期；抵达时同步校验开放时间、位置、天气、耗材和版本，条件仍成立才执行。失效则重新决策，不能自动换成另一种活动。导航同时考虑工作地点、区域中心、兴趣地点、补给不足、精力不足及公共工程。不存在远程钓鱼、远程捐助或隔空护理。

本职工作、阅读、休息、等待使用持久化 `localTask`。执行中不反复调用模型，到期由本地结算产物、体力和记忆，随后唤起下一次决策。路径由本地连续推进；户外活动沿用其持久化执行器。

观察动作候选不会推进随机数或消耗犯罪机会。犯罪机会仅在实际启动下一次 Jev 动作决策时采样。

## 决策时刻

抵达后优先执行已批准且校验通过的活动；活动失效、行动完成、等待结束、天气改变、本人文档改变及重要事件会使下一次决策就绪。快速上下文保留最近三次行动与到访意图，帮助识别无理由的往返。正在执行的持续任务、户外活动、交谈和移动不会因此逐帧重选；雷雨会中断露天工作与危险户外活动。

角色正在交谈或被玩家主动打断时，未完成本地任务不会发放产物。已故、服刑及儿童仍遵守各自原有规则，不进入成人动作选择。

## DeepSeek 的调用边界

- 首次、阶段目标失效或距离生成已满三个游戏日时调用 DS；每天仍检查有效性，条件未变则沿用，不请求。后台并发上限为 4。
- 本人文档变化、重要家庭／司法事件、明确目标受阻或连续三次行动失败才开放 `replan`。普通天气变化、正常完成工作和一般进展由 Jev 直接处理。
- 只有 Jev 选择 `replan` 才额外请求。每人每天最多一次，间隔至少 360 游戏分钟和 60 现实秒。已经失去触发条件的排队重规划会取消。
- 每个规划只做一次逻辑尝试，网络层保留一次瞬时错误回退；失败保留现有目标，不叠加另一轮自动规划重试。预算与暂停仍可阻止请求。
- 规划使用精简的本人上下文，输出最多 160 个中文字、512 tokens，提供可复用阶段优先级和天气备用方案，不编排不可执行的逐分钟脚本。
- 跨日、文档版本变化、重要新事件、死亡或服刑会使在途旧结果无法提交；普通交谈不使后台规划无谓失效。

NPC 每段交谈最多一次 DS 文字表达逻辑请求，失败或重启也不重置配额；之后仍由 Jev 选择意图，使用明确标注的本地表达。结束、拒绝、道歉和已批准秘密片段直接按意图表达。玩家开放式回复仍可按需调用 DS；DS 自由生成文本仍经过 Jev 核验，本地表达不伪装成 DS 生成。该策略会降低 NPC 闲聊措辞的多样性，以减少延迟和费用。

日终默认摘录已记录的本人亲历／承诺。显式设置 `DEEPSEEK_REFLECTION=true` 才调用 DS 反思。手动故事整理维持原有按需生成和缓存，不因后台节流被删除。

台账用途分别为 `daily-plan`、`replan`、`dialogue`、`reflection` 与 `benchmark-action`。已有的 `plan` 历史保留为旧版规划，不伪造费用节省。

## 旧存档与暂停

规划状态和本地任务随世界存档持久化，旧角色按需补充字段。已保存的人设、秘密、关系、记忆和 token 台账不重置。旧版未知日期的暂存规划不覆盖新策略下的目标；暂停期间的新规划暂存，继续时重新校验。后台中断保留尝试计数，避免重启绕过重试上限。

本工作区同时完成了移除离线补算的修改；本策略使用实时游戏时钟，停止服务或休眠期间不会补算角色行动。

## 验证

`tests/action-policy.test.ts` 覆盖场所与职业过滤、装备与天气限制、候选查询不推进随机、返回后的再次校验、本地任务不调用模型、暂停和重启、跨日规划复用、Jev 显式重规划、冷却与上限、慢规划不阻塞行动、过期计划和失败不重复排队、本地日终记忆。

运行 `node --import tsx scripts/action-policy-check.ts` 可在临时规则世界中检查三个完整游戏日，不触碰实际小镇、不调用外部模型，报告写入 `output/action-policy-three-days.json`。早期每日策略的常规规划机会为 24 × 3 = 72 次。现在无重大变化的三天复用场景只需 24 次，减少约 67%；有重大事件会提前更新。规则演示压缩现实时间，因此 60 秒冷却会影响重规划触发，不能当作线上用量承诺。`tests/ds-efficiency.test.ts` 另验证六轮 NPC 交谈的 DS 表达从最多六次降为一次、玩家回复保留 DS、失败配额持久化、抵达校验及重启。

### 本轮验证结果

- 全量 126 项测试通过；随后对本地对白措辞的调整另通过 DS 节流、实时对白和故事的专项回归。
- 三完整游戏日规则运行：34 次阶段规划、2 次重规划、152 次完成工作、34 段会话，真实 API 用量为 0。旧日更策略仅基础规划即 72 次；此处用于比较调度机会，不是线上账单对照。
- 单独三天规则模拟通过：3,601 个 tick、1,868 条事件、46 段会话。
- 关键节点仍同步：局部节点只等待相关居民；跨日／天气及出生／司法等待全镇。快照 `performance.synchronization` 和 `lastSynchronization` 提供原因、涉及角色与等待毫秒数，便于后续只读分析。
