# 溪谷镇：Agent 设计与性能实测

12 页中文技术 pitch，建议讲解 8–10 分钟，以下配时合计约 9 分 20 秒。内容快照：2026-09-27。

性能数据来自本项目既有真实 API 测试。本轮只整理文稿，没有追加付费测试。游戏时钟倍率、行动吞吐、单次行动延迟和浏览器帧率是不同指标，不能互相替代。

## 01 · 封面（20 秒）

溪谷镇是一个多 Agent 社交模拟。24 位初始成年居民各有职业、个人记忆和行动选择。本次重点是角色如何决策，系统实际跑得怎样，以及这些角色能做什么、经历什么。后续出生可能增加人口，24 是初始成年居民数。

封面为项目实际渲染截图，仅展示场景，不作为模型行为或性能证据。素材：`output/playwright/voxel-cloud-final.png`。

## 02 · 模型与运行时的职责分配（40 秒）

Jev 处理频繁发生的结构化判断：选行动、判断社交意愿、选对白意图、评分及核验表达。DeepSeek 负责按需规划和自然语言表达。本地 Harness 生成合法候选，调度请求，并将通过校验的选择落实到世界。

Jev Choice 的置信度反映分布集中程度，不等于选择正确率。Score 是等级加权结果，不能一律视为概率。本地规则保留最终执行权。日终默认采用本地经历摘录，DeepSeek 反思需可选配置。

来源：`server/models.ts`、`server/world.ts`、`server/actions.ts`、`docs/sources/jev-api-2026-09-27.md`。

## 03 · 单个 NPC 的决策闭环（50 秒）

沿图讲解感知、准备、决策、执行、记忆五步。青色为高频 Jev 判断，紫色虚线为按需 DeepSeek 支持。模型选择活动，本地执行寻路与持续任务；模型无需每帧介入。

行动、对白、后台分别限流。后台规划不占行动忙碌锁，已有目标可以继续执行。流程适用于成年自由居民。计划复用和表达复用是调度机制，不直接证明某个固定百分比的性能提升。

图源：`docs/slides/figures/npc-agent-flow.tex`。实现：`server/world.ts`、`server/planning.ts`、`server/realtime.ts`、`server/actions.ts`。

## 04 · 角色上下文与行动契约（45 秒）

每位居民只读取本人的人设、需求、秘密、记忆及相关关系信息。快速工作集包含四条重要记忆、四条当日记忆和最近三次行动，完整历史另外保存。传闻作为 belief 进入个人认知，不直接改变已验证世界事实。

用“去图书馆阅读 20 分钟”解释行动契约：一次选择同时批准目的地和抵达后的活动，途中由本地执行，提交和抵达时再验证资源、天气与版本。该例是合法候选示意，不是某次模型输出。

来源：`server/realtime.ts`、`server/actions.ts`、`server/world.ts`。

## 05 · 对白链路与信息边界（45 秒）

Jev 先判断意图与关系影响，DeepSeek 仅收到安全角色描述、公开信息和获准事实，自由生成文字再经过 Jev Noul 核验。低于 0.85 时采用明确标记的本地表达。提交前还会复查会话轮次、距离、版本与披露条件。

每段 NPC 会话最多一次 DeepSeek 表达逻辑请求；逻辑请求可能含底层重试。玩家开放式回复仍可按需生成。拒绝、结束等已知意图可以直接使用本地表达。

来源：`server/world.ts` 的 respond / commitSpeech。

## 06 · 异步调度与按需规划（45 秒）

三个任务池的并发上限分别是行动 12、对白 3、后台 4。有效计划最多复用三天，重大变化才开放额外重规划，每人每天最多一次，同时受 360 游戏分钟和 60 现实秒的冷却限制。规划失败时保留原目标。

个人事件只等待相关居民，但跨日、天气等全局节点仍需要同步，这会放大慢请求的影响。预算先预留再按 usage 结算，未知用量仍占预算。

来源：`server/planning.ts`、`server/realtime.ts`、`server/world.ts`、`server/store.ts`。

## 07 · 系统对照：只替换 Jev 承担的判断（70 秒）

这是一组系统替换实验：相同初始存档与核心调度，将原 Jev 判断职责交给 DeepSeek，原有规划、表达与三阶段对白流程继续保留。没有把链路合并成一次请求，也不是独立比较两个模型的裸调用速度。

Jev + DS 跑了 92.42 秒，替换版跑了 80.13 秒。单位游戏小时费用从 ¥0.0306 升到 ¥0.0926，约为 3.03 倍。目标均为 6×，本轮实际平均分别 5.39×、5.92×。替换版没有让整体时钟推进变慢，但完整行动调用的中位延迟上升，P95 反而下降，不能用单个数字宣布谁全面更快。

限制：各只有一轮，轨迹分叉；替换版因 ¥0.60 预算预留不足提前停止；DS 自评置信度没有与 Jev 校准，并出现四次 JSON 解析失败。费用是本地估算，不是供应商账单。此处的“完整行动调用”包括失败或暂存等结果，与下一页只统计已提交行动的口径不同。

来源：`docs/system-replacement-comparison.md`、`output/system-measure/comparison.json`、`summary.json`、`replacement-summary.json`。

## 08 · 单个行为：从可决策到后端生效（50 秒）

本页统计当前 Jev + DS 基线中 275 次已提交行动，从 queuedAt 到 appliedAt，包含 29 次本地规则覆盖，不包含三次失败和五次暂停暂存。中位 490 ms，P95 为 2,476 ms，最长 9.60 秒。主要耗时在模型调用、重试与验证，本地排队和提交通常只有毫秒量级。

全镇合计 2.98 次行动/现实秒，不是每个角色都每秒行动三次。单个角色启动间隔中位 7.46 秒。此测量不含请求前的冷却、整个活动完成时间或前端显示时间。阶段分位数独立计算，不能相加得到总分位数。

来源：`docs/current-system-live-measurement.md`、`output/system-measure/action-latency.json`。

## 09 · 压力测试：时钟更快，行为密度会下降（70 秒）

同一新起点、24 位成年人，八轮各约 45 秒，使用真实 Jev + DS，只在隔离副本放开倍率上限。最高观察到的平均时钟倍率是 114.08×，最高观察到的行动吞吐是另一轮的 13.54 次/秒。它们不是同一轮，也不是已证实的稳定极限。

48× 首轮实际达到 45.78×，复测却降到 13.36×，行动 P95 从 0.57 秒增至 6.79 秒。长尾请求被全局同步放大，因此没有足够证据承诺稳定最高倍率。单角色约 1.5 秒调度节流，24 人自动行动启动的结构上限约为 16 次/秒。

表格末列只计完成的工作、阅读、休息，不是所有事件。192× 档的此类活动密度比本轮 6× 低约 79%，说明时钟快进并不意味着每游戏小时的人物生活同样丰富。顺序短测受网络波动和轨迹分叉影响，没有测试浏览器 FPS。

来源：`docs/system-performance-limit.md`、`output/system-stress/analysis.json`。

## 10 · 角色能够选择的行为（50 秒）

本地按当前状态生成最多 24 个合法候选，Jev 从中选择。这些候选覆盖移动休息、职业工作、阅读购物、户外活动、社会交往及长期选择。角色不会每次都获得整个行为全集。

举三个具体例子：带鱼饵去河边钓鱼；到本人工作场所持续工作；向另一位居民发出邀请，由对方决定是否接受。移动与活动由本地持续执行，完成后更新物资、体力与记忆。医生护理是恢复体力，尚不是完整疾病诊疗系统。

来源：`server/actions.ts`、`server/outdoor-engine.ts`、`server/society.ts`。

## 11 · 小镇内置的十种生活事件（40 秒）

十种事件为猫咪带路、飞帽奇遇、失物归还、爱心面包、街角即兴曲、速写赠礼、野莓惊喜、屋檐听雨、萤火微光、同款包裹乌龙。

这些是本地按条件和概率触发的内置事件，包含地点、时间、天气、职业、物资与空闲条件。事件更新情绪、体力、库存或关系，并记录参与者的亲历，之后 Agent 再依据新状态选择行动。支持自然与展示节奏，冷却减少重复。事件文本与模型即时生成对白应分别介绍。

来源：`server/incidents.ts`、`shared/incidents.ts`。

## 12 · 约定、家庭与司法形成长期后果（35 秒）

小事件之外，系统还保留跨时段后果：约定可以兑现或因天气延期；婚姻与育儿要求双方独立同意并满足资格；严格条件下的致命冲突会触发调查与司法状态。天气和公共建设也会改变未来的可用活动。

结尾落到 Agent 闭环：事件成为个人记忆和世界状态，再影响下一次选择。上述机制不是预设必然剧情。当前儿童保持幼年，没有完整代际成长，不能根据构造的验收场景推算自然发生率。

来源：`server/world.ts`、`server/society.ts`、`shared/weather.ts`。
